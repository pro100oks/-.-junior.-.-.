##Архитектура PUSH-уведомлений 
Схема описывает верхнеуровневую архитектуру отправки push-уведомлений в мобильном приложении интернет-магазина.

###Источники событий
Уведомления инициируются тремя микросервисами: сервисом корзины(например, корзина брошена и долго не оформляется), сервисом заказов(изменение статуса заказа, отмена) и промо-сервисом(рекламные рассылки). Каждый из них при наступлении нужного события отправляет сигнал на сервер уведомлений.

###Сервер уведомлений
Получает события от микросервисов, определяет какое именно уведомление нужно отправить и какому пользователю. Для этого он обращается к базе данных токенов.

###База данных токенов
Хранит уникальные id устройств (device tokens). Нужно, чтобы знать на какое устройство отправлять уведомленияю

###Внешние шлюзы доставки
Сервер уведомлений передаёт задачу внешним шлюзам.

FCM(Firebase Cloud Messaging) — доставляет уведомления на Android-устройства
APNs(Apple Push Notification service) — доставляет уведомления на iOS-устройства

###Регистрация токена
При первом запуске приложения телефон пользователя получает уникальный токен(id) от FCM или APNs и отправляет его на сервер уведомлений, где он сохраняется в базе данных. При надобности доставить уведомления, сервер использует этот токен, чтобы понимать какое устройство должно получить уведомление.
